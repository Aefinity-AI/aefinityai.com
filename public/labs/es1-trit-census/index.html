E-S1: how far can a ternary 2B model be compressed without loss?

The same picture, in words

Question
Can a 1.58-bit AI model be squeezed much smaller without losing anything?
Why it matters
Could a ternary model be made much smaller without losing anything?
How the test works
  1. Count all 2,084,044,800 weights in the 210 body tensors.
  2. Compress them with rANS, xz and zstd.
  3. Verify the round trip byte for byte.
What we found
1.532 bits per weight. The best of the lossless coders tested (zstd -19) reached 1.532 bits per weight against 2.000 for the engine's current packing. The round trip was byte-exact with 0 mismatches. Against ideal ternary packing (1.600) the saving is about 4%.
What it means
Pretrained ternary weights are close to uniform, so lossless coding gains little; real savings would need changes to the model. One model, one machine; coding speed not measured.
Everyday comparison
Like zipping a file of coin flips: there is almost no pattern to squeeze out.

01Why it matters

Could a ternary model be made much smaller without losing anything?

02Method, step by step

  1. Count all 2,084,044,800 weights in the 210 body tensors.
  2. Code them with rANS, xz and zstd.
  3. Verify the round trip byte for byte.

Method as recorded

Census and lossless coding (rANS, xz, zstd) of all 2,084,044,800 weights in the 210 body tensors of the BitNet-b1.58-2B engine model file aegis_pruned_model.safetensors, with a byte-exact round trip, on one Dell i5-5200U. Counts and byte sizes only. Run by us.

03Results, exact and sourced

  1. R1The best of the lossless coders tested (zstd -19 on packed bytes) reached 1.532 bits per weight, 399,113,010 bytes, against 2.000 bits per weight for the engine's current packing.

  2. R2The round trip was byte-exact on every tensor, with 0 mismatches.

  3. R3The trits are near-uniform, so the weights compress only a little.

04What it does NOT show

Anything about coding speed or changes to the model.

05Scope and caveats

  • One model, one machine (Dell i5-5200U).
  • Against ideal trit packing (1.600 bits per weight) the saving is about 4%. The 23% saving against the engine's file comes only from that file spending 2 bits per trit.
  • Generic zstd beat the one-trit-context rANS coder on the gate and up projections. The source says this is worth about 1% overall and that a row/column-adaptive model is the only remaining lossless headroom. That was not tested here.
  • Going below this level needs model changes (sparsity), which this lab does not make.
  • Counts and byte sizes only. Coding speed was not measured.
  • Run by us; no unaffiliated reproduction.

06Outcome

Null

No effect found, or nothing yet to report.

07What we learned

Pretrained ternary weights are close to uniform, so lossless coding gains little. Real savings would need changes to the model, not a better coder.
