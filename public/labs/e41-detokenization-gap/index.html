L21 2026-09-10 Negative Q5 · Rebuilt from the written spec

E41: the spec pins how text becomes tokens, but not how tokens become text

QuestionCould two certified programs agree on every number in a receipt yet disagree on what it says?

Run by us; no unaffiliated reproduction

The test in one picture

Question, method, result and meaning, in plain words. The sourced detail is further down the page.

The same picture, in words

Question
Could two programs that both follow the spec agree on every digest yet print different text?
Why it matters
A receipt is read by people. If two conforming programs can print different text for the same digests, the receipt's meaning is not pinned.
How the test works
  1. Read the spec against the tokenizers of the two named models.
  2. Count vocabulary entries and output slots where turning ids back into text is ambiguous.
  3. Probe with small Rust examples.
What we found
313 + 271 ambiguous entries. 313 of SmolLM2's 49,152 vocabulary entries (0.64%) are not valid text on their own. 271 of Qwen's 151,936 output slots map to no string. All 17 of SmolLM2's special tokens decode to text that re-encodes to different ids. So two conforming programs can disagree on what a receipt says.
What it means
Matching digests is not the same as matching meaning: the spec pins text to tokens but not tokens to text. A gap in our spec, not a defect in the models. It does not show that any real receipt was misread.

01Why it matters

A receipt is read by people. If two conforming programs can print different text for the same digests, the receipt's meaning is not pinned.

02Method, step by step

  1. Read the spec against the tokenizers of the two named checkpoints.
  2. Count vocabulary entries and output indices where turning ids back into text is ambiguous.
  3. Probe with small Rust examples.

Method as recorded

Read CIS-2 spec v0.3b against the tokenizers of the two checkpoints it names (SmolLM2-135M and Qwen2.5-0.5B) and counted where turning ids back into text is ambiguous. Probes were Rust examples run on one host (Debian 13, x86_64 VM). Run by us.

03Results, exact and sourced

  1. R1Two conforming implementations can disagree on a receipt's text.

  2. R2313 of SmolLM2's 49,152 vocabulary entries are not valid UTF-8 on their own.

  3. R3271 of Qwen's 151,936 output indices map to no string in the tokenizer files.

  4. R4All 17 of SmolLM2's special tokens decode to text that re-encodes to different ids, so a rendered control token cannot be told from text spelling it.

04What it does NOT show

That any real receipt was misread, that other tokenizers behave the same, or that it affects conforming runs on Qwen.

05Scope and caveats

  • A gap in our spec (v0.3b), not a defect in the checkpoints; recorded as erratum E-14.
  • Two checkpoints only; the counts are properties of those artifacts, not of tokenizers in general.
  • The 271 unmapped Qwen ids did not win the argmax on one prompt over 16 decode steps (untriggered on this vector, not shown impossible); no search over prompts was run.
  • Qwen's tokenizer.json is refused by the spec's conforming path, so the Qwen gap does not affect conforming runs.
  • No survey of other inference specifications; no claim the gap is unusual.
  • Run by us on one machine; no unaffiliated reproduction.

06Outcome

Negative

The claim or approach failed, or we retracted it.

07What we learned

Matching digests is not the same as matching meaning. The missing piece is a text-level definition; whether v0.4 specifies detokenization or declares it out of scope is a spec-owner decision.
