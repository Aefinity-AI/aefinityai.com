Question
Could errors inside the model cancel out, so the final answer looks right while the inside is wrong?
Why it matters
Errors inside a model could cancel, so the final answer looks right while the middle is wrong.
How the test works
  1. Feed the same token ids to our verifier and to a Hugging Face transformers fp32 pass.
  2. Compare every intermediate tensor.
  3. Start with one prompt, then widen to six prompt cells on each of two models.
What we found
144,825 tensors compared. The widened runs compared 144,825 tensors across two models. The single-prompt worst disagreement was 9.9e-5 (Qwen). Widening corrected our own published SmolLM2 worst case to 3.406e-05, which is 1.53 times the number we first published.
What it means
Agreement is to about 1e-5 relative (up to 1e-4 on Qwen), not bit-exact, because the comparison uses a different implementation on purpose. A maximum from one input is only that input's maximum.
Everyday comparison
Like checking every line of a sum against a second person's working, not only the final total.

01Why it matters

Errors inside a model could cancel, so the final answer looks right while the middle is wrong.

02Method, step by step

  1. Feed the same token ids to our verifier and to a Hugging Face transformers fp32 forward pass.
  2. Compare every intermediate tensor.
  3. Start with one prompt, then widen to six cells on each model.

Method as recorded

Teacher-forced comparison of every intermediate tensor of the verifier against a Hugging Face transformers fp32 forward pass: one prompt on SmolLM2-135M and Qwen2.5-0.5B (E28), then six prompt/length cells on SmolLM2-135M (E36) and six on Qwen2.5-0.5B (E37). Run by us.

03Results, exact and sourced

  1. R1E28: 13,452 intermediate tensors (one prompt, 19 positions, two models: SmolLM2-135M and Qwen2.5-0.5B) compared; worst relative L2 disagreement 9.9e-5, on one tensor of one model (Qwen). This is a single-prompt maximum, not a bound for the model.

  2. R2E36 corrected our own published worst case: over six SmolLM2-135M prompt cells (80,565 tensors) the worst was 3.406e-05, 1.53 times the 2.228e-05 E28 published from its single SmolLM2 prompt.

  3. R3E37: six Qwen2.5-0.5B cells add 64,260 tensors; with E36 that is 144,825 tensors across two architectures. On Qwen, E28's 9.923e-05 turned out to be the six-cell maximum (rel_rms rose to 2.883e-03); the earlier layer-ratio bounds were per-prompt and were corrected (erratum E-9).

04What it does NOT show

Bit-exactness (the oracle is a different implementation), tokenization, or all prompts.

05Scope and caveats

  • Agreement is to about 1e-5 relative (up to ~1e-4 on Qwen), not bit-exact, because the oracle is a different implementation and must not be bit-exact; this is an accuracy check, not a determinism check.
  • Two small models; six prompts per model is still not all prompts (E37 states this).
  • The Qwen runs use supplied token ids from the oracle tokenizer and are not conformance runs; they attest to spec sections 4-11 only, not tokenization (section 3).
  • The oracle (transformers) is an independent implementation, not ground truth.
  • Not run in CI; reproducible on demand with the model artifacts and torch.
  • Run by us; no unaffiliated reproduction.

06Outcome

Positive

The check worked as expected, within the stated scope.

07What we learned

A maximum measured on one input is only that input's maximum. Widening the sweep corrected our own published number on SmolLM2 (1.53x higher), and on Qwen showed the single-prompt figure happened to be the worst case, so it was unknown, not reliably low.
