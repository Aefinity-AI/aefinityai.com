One flipped bit in the weights: which checks notice?

Question, method, result and meaning, in plain words. The sourced detail is further down the page.

The same picture, in words

Question
If one bit of an AI model's weights is silently corrupted, can you tell by re-reading its output, or must you check the computation itself?
Why it matters
Weights are files that can be corrupted or tampered with. Re-reading the answer is the cheap check; checking the computation is the expensive one. We wanted to know how much the cheap one misses.
How the test works
  1. Take one pruned BitNet-2B model and one prompt, 64 tokens.
  2. Flip single bits in the weights: 50 trials, then 295 trials across tensor classes.
  3. Run three checks on each corrupted run: same text, same top-5 candidates, same computation digest.
  4. Count misses with 95% intervals; recount from raw logs on a second host.
What we found
182 of 247 missed by text. In the 295-trial run, 247 flips changed the model's output scores. Text replay missed 182 of them and the top-5 check missed 82. The computation digest missed 0, which is true by construction. 43 flips changed nothing in the computation.
What it means
Comparing output text missed most of the real changes in this test. One model, one prompt, flips chosen by our harness, no adversary. The informative numbers are the two weaker checks' misses, not the digest's built-in 0.
Everyday comparison
Like judging a cake by its look: a swapped ingredient can slip past, but re-baking it step by step shows the difference.

01Why it matters

Weights are files that can be corrupted or tampered with. Re-reading the answer is the cheap check; checking the computation is the expensive one. We wanted to know how much the cheap one misses.

02Method, step by step

  1. Take one pruned BitNet-2B checkpoint and one prompt, 64 greedy tokens.
  2. Flip single bits in the weights: Experiment 1 used 50 trials, Experiment 2 used 295 trials spread across tensor classes.
  3. Run three kinds of check on each corrupted run and count the misses, with 95% Wilson intervals.
  4. Recount everything from the raw per-trial logs on a second host.

Method as recorded

Pruned BitNet-2B checkpoint, prompt 'Once upon a time', 64 new tokens, greedy, one host (one of our own machines). Experiment 1 (moat-3): 50 trials (5 no-flip controls, 40 random low-mantissa flips in bits 0-4, 5 forced bit-7 flips); A = text/argmax replay, B = top-5 logit-set match, C = full witness-chain digest match. Experiment 2 (moat-3b): 295 trials stratified by tensor class plus a bit-position sweep; the harness source (commit 1567ee1, header lines 28-30) defines A = generated token ids identical to the clean baseline, B = top-5 logit index set identical at every step, C = witness-chain digest match, which agrees with the write-up's summary tables. The write-up's setup paragraph describes Experiment 2's A and B differently (run completed without error; receipt accepted); the harness code is the authority. Wilson 95% intervals computed for the doc; counts recounted from raw per-trial logs on a second host (recomputation only, not re-inference). Harness commits (14ef1a1, 1567ee1) are public; we did not rebuild them for this summary.

03Results, exact and sourced

  1. R1Experiment 2 (295 trials): of 247 trials where the output logits changed, text replay (A: same generated token ids) missed 182. The harness source defines A this way; the write-up's setup paragraph describes A differently, but its tables and the code agree.

  2. R2Experiment 2: the top-5 logit-set check (B, labelled 'top-k / receipt-style' in the write-up's table) missed 82 of the same 247.

  3. R3The witness digest row is 0 of 247. The document says this is exact by construction, since a digest miss and a C-fail are the same event.

  4. R4Experiment 1 (50 trials): text replay passed 3 corruptions that the digest caught (trials 16, 25, 47). Top-5 replay also failed on all 3, so its miss count was 0 at this sample size.

  5. R5Null result: 43 flips (37 of 70 SCALE_FFN and 6 of 35 TRIT_FFN trials) left the witness digest identical to the clean baseline. The digest by design stays silent on these, and a byte-level check would flag them.

  6. R6The write-up corrected its own original report after the independent recount: trial 47 was a bit-7 flip from the random set, not one of the 5 dedicated high-bit control trials.

04What it does NOT show

Adversarial tampering (none was tested), other prompts or models, or timing. The digest's 0 of 247 is exact by construction, so it is not evidence about the digest; the informative numbers are the misses of the other two checks.

05Scope and caveats

  • The digest's 0/247 is exact by construction (C is defined as a digest or baseline-output mismatch); the informative numbers are how often A and B miss.
  • The write-up's setup paragraph describes Experiment 2's A as 'inference completed without error' and B as 'receipt accepted'. The harness source at commit 1567ee1 defines A as identical generated token ids, B as an identical top-5 logit index set and C as a witness-digest match, matching the write-up's tables; we follow the code.
  • Experiment 1's random flips were low-mantissa bits 0 to 4 only (plus 5 forced bit-7 flips). Flips were chosen by the harness, not an adversary.
  • B is the top-5 logit-set check in both experiments per the harness source; the write-up's prose calls Experiment 2's B a receipt check. The two experiments' counts are still reported separately, not merged.
  • In Experiment 1 every method caught all 5 forced high-bit flips. In Experiment 2 the EMBED class (80 trials) was missed by both A and B 80 of 80 times.
  • Embedding result: EMBED C-fail was 80/80 for the fixed prompt only. The unused-embedding-row case was not tested.
  • No adversarial (optimised) tampering was tested. No timing claims are made.
  • One pruned 2B checkpoint, one prompt, one hardware family; second host recomputed counts from logs only. The checkpoint is not linked publicly, so outsiders may not be able to rerun as-is.
  • Run by us; no unaffiliated reproduction.

06Outcome

Positive

The check worked as expected, within the stated scope.

07What we learned

In the larger run, among the 247 trials where the output actually changed, the text-replay column missed 182 and the top-k/receipt-style check missed 82. Some flips (43) changed nothing in the computation. A check on the computation itself is by definition silent only on flips that changed nothing, but that 0/247 is true by construction, so the informative finding is how often the weaker checks miss. Single prompt and model, harness-chosen flips, no adversary.
